# 8.1 — Capital Farm mechanics parity checklist

**Purpose:** Track **simulation parity** with the frozen MVP (`EconomyGame_MVP (6).html` + `js/*.js`), not UI parity. Godot is allowed — and expected — to present the game differently.

**Oracle:** Play or inspect the HTML MVP; compare numbers and state transitions. Use GUT tests for anything deterministic.

**Scope:** **Capital Farm** (`mode: arcade`) first. **Securities** and **bank loans** are verified in Godot (8.2). Simulator mode and legacy seven-improvement path remain **Phase 6 / deferred**.

**Related:** Architecture and phases → [`8.0_godot_migration.md`](8.0_godot_migration.md) · Community social mechanic → [`8.3_community_social_mechanic.md`](8.3_community_social_mechanic.md)

---

## Definition of done (mechanics)

Capital Farm parity is achieved when a player can:

1. Start a run, spend AP on acquisitions/upgrades/financing, advance quarters, and reach **win ($10M NW)**, **loss (insolvency)**, or **timeout (30 turns)** with the same *rules* as the MVP.
2. Experience the same economic consequences: debt service, synergies, capacity strain, seller notes, rival contests, upgrade drift, etc.
3. Prove core math via GUT + at least one golden JSON fixture from the MVP.

UI may look nothing like the HTML game as long as every mechanic is **reachable and readable enough to test manually**.

## Minimal test UI (not MVP UI)

These are **usability gates**, not design targets. Goal: comfortable manual QA without rebuilding the HTML layout.

### Current pain (as of this doc)

- Three equal columns (Portfolio | Opportunities | Supply Chain) on one screen → **cramped**, long wrapped labels, many buttons per opp row.
- No run log visible (`run_log` exists in sim but is not shown).
- ~~Debrief is a single line; hard to verify quarter-over-quarter changes.~~ **Fixed (8.2):** turn debrief modal + collapsible dashboard card + live progress graph.
- Modals (negotiation, shortage, improve) compete for space; negotiation panel was fixed once but dashboard density remains high.

### Test UI checklist

- [ ] **Dashboard layout:** replace 3-column cram with one of: tabbed panels, collapsible sections, or primary + detail split — more vertical scroll, less horizontal squeeze
- [ ] **Scroll + minimum widths:** each major panel scrolls independently; opportunity rows use vertical action stack or overflow menu when narrow
- [ ] **Readable defaults:** base font ≥ 14px equivalent; consistent money formatting; line spacing on multi-line business/opp cards
- [ ] **Run log panel:** last N `run_log` entries visible (filter by turn optional)
- [x] **Quarter summary:** after advance, turn debrief modal + dashboard card (rev / cost / debt service / profit / synergy highlights; expandable detail)
- [x] **Status bar:** turn, cash, NW, debt, AP, reputation — always visible (`dashboard.tscn` TopBar)
- [x] **Game over screen:** `run_report.tscn` — end-run reason + final NW + NW/Cash/Debt progress graph + strategy extras
- [x] **Controls map 1:1 to commands:** every player action dispatches `Game.apply_command()` — no sim logic in UI scripts

**Explicit non-goals:** supply-chain diagram animations, Chart.js graphs, milestone fanfare styling, field guide, HTML panel parity.

## P0 — Core loop integrity

*Without these, the run doesn’t behave like Capital Farm.*

### Turn economy

- [x] **AP reset on advance:** turn 1 → 3 AP; later turns → 2 AP (`maxActionPoints`)
- [x] **AP gate all spending actions:** Buy, Investigate, Negotiate/Contest, Improve, Take loan, Sell — fail or disable at 0 AP
- [x] **Negotiation blocks advance** until closed (already enforced)

### Opportunity lifecycle

- [x] **Persist opportunities across turns** — do not `clear()` entire list each refresh
- [x] **Decrement `expiresIn`** each advance; remove at 0
- [x] **Survivor priority:** carry forward in-progress listings before filling fresh slots (MVP cap ~6 regular + persistent level-ups)
- [x] **Display expiry** in test UI (e.g. “2 qtrs left”) — needed for QA

### Deal closing & finance

- [x] **`settleAcquisitionFinance` port:** cash at closing + seller note for remainder (`LoanSystem` or `finance_system.gd`)
- [x] **Negotiation close uses financing** — partial cash offers create 8-qtr seller note, not “need full cash”
- [x] **Reputation +2 on closed deal** (+3 with `relationship_capital` edge when edges exist)
- [x] **Buy Now** = pay ask, 1 AP, no negotiation upside (already close; wire AP + label)

### Win / loss

- [x] **Insolvency:** negative cash beyond reputation-based credit → `game_over` loss
- [x] **Win:** net worth ≥ **$10,000,000** → `game_over` win
- [x] **Timeout:** turn > 30 → win if NW ≥ target else timeout (match MVP rule)

### Tests (P0)

- [x] GUT: AP reset after advance
- [x] GUT: opportunity survives one turn with `expiresIn` decrement
- [x] GUT: seller-note close creates loan + reduces cash correctly
- [x] GUT: insolvency and win thresholds

## Suggested implementation order

1. **P0 turn economy** — AP reset, AP gates, opp persistence/expiry  
2. **P0 seller notes** — unlocks real negotiation  
3. **P0 win/loss** — runs can end correctly  
4. **Test UI layout pass** — unblocks manual QA for everything after  
5. **P1 chain hints + external revenue + sell**  
6. **P1 real estate** (if chain completeness needs it)  
7. **P2 urgents → milestones → level-ups**  
8. **P2 market events + wildcard**

## Manual smoke script (after P0)

1. New Capital Farm → starter opp visible → Investigate → Negotiate with seller note → close with partial cash → verify loan in portfolio.  
2. Advance 3 turns → AP refills → opportunities expire correctly → debt service hits P&L.  
3. Acquire two linked businesses → set supply policy → verify synergy line on dashboard.  
4. Accept bank line of credit → advance → principal amortizes.  
5. Trigger rival contest → win or lose listing.  
6. (When wired) reach insolvency or $10M NW → game over screen.
