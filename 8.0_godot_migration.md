# EconGame 8.0 — Godot 4 Migration Plan

Planning document for restructuring the HTML MVP into a maintainable **Godot 4** project while preserving gameplay parity.

**Baseline:** `EconomyGame_MVP (6).html`, `js/farm-supply-chain.js`, `js/business-upgrades.js`, `js/supply-chain-view.js`, `js/rival-farmer.js`, `js/farm-animal-npc.js`

**Design principle (north star):**  
The simulation is the product. UI is a view. Data is authored. Every phase must keep a runnable build and a way to prove parity with the MVP.

**Non-goals for early phases:** art polish, 3D, multiplayer, shipping builds, replacing the AI proxy with in-engine LLM.

---

## 1. Current state (what we’re migrating)

| Layer | Location | ~Size | Notes |
|-------|----------|-------|-------|
| Core sim + most UI | `EconomyGame_MVP (6).html` | ~5,200 lines, ~230 functions | State, turns, finance, negotiation rules, opportunity gen, DOM render |
| Supply chain engine | `js/farm-supply-chain.js` | ~1,700 lines | Templates, connections, synergies, capacity, shocks, strategy |
| Five-axis upgrades | `js/business-upgrades.js` | ~850 lines | 7.0 tracks, preview, quarterly drift |
| Supply chain UI | `js/supply-chain-view.js` | ~550 lines | Diagram, ghost preview, lever strips — **view only** |
| Rival contests | `js/rival-farmer.js` | ~1,380 lines | Cassius Rowe, 3-way acquisition |
| Animal NPC layer | `js/farm-animal-npc.js` | ~670 lines | Species traits, utility bonuses, prompt decoration |
| Regression guard | `scripts/regression-*.js` | 6 suites | Node parity tests |
| Local AI | `ai-proxy/server.js` | small | Ollama bridge; stays external for now |

**Problem:** logic, presentation, and content are entangled. Capital Farm features already leak across HTML + modules. Further growth (7.0+, new modes) will not scale in a single file.

**Target:** Godot project where **simulation code has zero node references**, content lives in **Resources**, screens are **scenes**, and the HTML MVP remains frozen as a parity oracle until cutover.

### Layer rules (enforce in code review)

1. **`core/`** — deterministic, unit-testable. Input: `RunState` + command. Output: new state + event list. No `get_node`, no `Control`, no HTTP.
2. **`data/`** — balance and content. Designers edit `.tres` / CSV / JSON; code reads via registries loaded at startup.
3. **`ui/`** — reads state, dispatches commands to `Game` / systems, listens to `EventBus`. No economy formulas in UI scripts.
4. **`autoload/`** — wiring only: save/load, scene transitions, AI client, RNG seed for run.

### Godot-specific choices

| Concern | Choice | Why |
|---------|--------|-----|
| Language | **GDScript** | Fast iteration, native Resources, matches team direction |
| UI | **Control nodes + Theme** | MVP is panel-heavy; no need for immediate-mode HTML strings |
| Data | **Custom Resources** for templates; **JSON** for large registries if needed | Inspector-friendly + diffable |
| Signals | **EventBus autoload** + typed signals on `Game` | Decouple UI from systems |
| Saves | **`RunState.to_dict()` / `from_dict()`** | Match MVP save shape early for fixture import |
| Tests | **[GUT](https://github.com/bitwes/Gut)** | Standard Godot unit-test addon |
| RNG | **Seeded `RandomNumberGenerator` per run** | Replay regressions |

- Single source of truth moves to Godot `data/` — update docs (7.0) to reference Resource paths, not JS line numbers.
- Keep numeric tables from `7.0_business_upgrades.md` as design spec; implement in `UpgradeTrackDef` resources.

### Strings & flavor
- Banter arrays (rival, species) → JSON or `.tres` with `Array[String]` — avoid hardcoding in system logic.

## 7. Testing strategy

| Layer | Tool | When |
|-------|------|------|
| Core math | GUT unit tests | Every commit touching `core/` |
| Golden saves | Fixture JSON from MVP | After each system port |
| Node regressions | `npm test` | Until GUT coverage ≥ Node coverage |
| Manual smoke | 6.0 Phase 0 script | Each phase exit |
| AI negotiation | Manual + proxy health | Phase 5+ only |

**Fixture workflow:**
1. Play MVP to interesting state.
2. `copy(JSON.stringify(S))` in browser console → `tests/fixtures/capital_farm_turn12.json`.
3. GUT loads fixture into `RunState.from_dict`, runs system under test, asserts expected numbers.

## 8. Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Big-bang rewrite stalls | Phase 1–2 headless first; UI only after math proven |
| Silent math drift | Golden fixtures + tolerances documented; no “looks right” |
| UI scope creep | Control layout MVP-first; defer graph animations |
| AI proxy coupling | `AiClient` interface; swap to embedded LLM later |
| Two codebases diverge | Freeze HTML features; changelog per phase |
| Godot Resource merge pain | Text `.tres` where possible; JSON for huge tables |

## Appendix B — Turn pipeline (target)

```
AdvanceTurn command
  → pre_turn hooks (wildcard, rival contest check)
  → resolve player actions consumed this turn
  → SynergySystem.compute
  → UpgradeSystem.quarterly_drift (manager passive)
  → FinanceSystem.compute_quarterly_run_rates
  → resolve_cash_flow (debt, opex, revenue)
  → MarketSystem.tick (securities, events)
  → OpportunitySystem.refresh
  → post_turn (reputation, milestones, season)
  → EventBus.turn_advanced.emit(new_state)
```

This mirrors the implicit order in the HTML MVP — verify exact order against `advanceTurn` / `endTurn` when porting Phase 1c.
