# EconGame 6.0 — Supply Chain Hierarchy Checklist

Planning document for **MVP (6)**: the supply-chain hierarchy mechanic from `docs/Supply_Chain_hierarchy_mechanic.docx`.

**Baseline:** `EconomyGame_MVP (6).html` (forked from archived MVP 5). MVP 5 lives in `prevVersions/`.

**Design principle (north star):**  
Every turn should answer: *“What’s my best move right now, and why?”* — now with **layer identity** (upstream / processing / infrastructure / consumer), **capacity tradeoffs**, and **visible leverage**.

**Core accounting rule (non-negotiable):**  
Internal links are **cost savings / reliability / utilization**, not stacked portfolio revenue. Consolidated P&amp;L = external consumer revenue + external contract revenue − operating costs − debt. Never double-count vertical integration as fake top-line growth.

**Simulation boundary:** Keep **authored percentage effects** — no unit inventory, batch tracking, or contract-by-contract ledger in 6.0.

## Phase 2 — Utilization & capacity (core gameplay)

Extend synergy math with **fulfillment ratio** without commodity simulation.

### Engine (`js/farm-supply-chain.js`)

- [x] **`computeDownstreamDemand(supplierTemplateId, state)`** — count active owned customer links + optional “export slot” weight
- [x] **`utilizationRatio(supplier, demand, capacity)`** — `min(1, demand / capacity)`; flag `overCapacity` when &gt; 1
- [x] Apply **`fulfilledEffect = baseEffect × utilization`** (or strain curve) in `computeSynergies` / `applyToBusiness`
- [x] Generalize strain beyond Repair/Cold Storage to **upstream producers** when over-allocated
- [x] **`portfolioRiskSummary`** includes utilization % per strained asset

### Shortage events

- [x] When any owned upstream/infra asset is **&gt;100% requested capacity**, trigger **shortage notice** (center panel + log)
- [x] Player must resolve before next Advance Turn OR auto-applies last policy (design choice — document in code comment)

### Allocation policies (per upstream + infrastructure asset)

Store on asset or global `state.supplyPolicies[templateId]`:

- [x] **Portfolio First** — owned downstream priority; external/rent bonus reduced; relationship penalty on hypothetical external clients
- [x] **Highest Bidder** — maximize short-term supplier-side lift; owned downstream may face shortages
- [x] **Contract First** — stable cash flow; less spike upside (stub OK if no external contracts yet)
- [x] **Balanced** — proportional split; moderate everything

Policy UI:

- [x] Shortage modal or center-panel picker (4 buttons + one-line effect summary)
- [x] Changing policy costs **0 AP once per shortage** OR **1 AP** anytime (pick one — default 0 AP on shortage)
- [x] Show current policy on portfolio row for assets that support allocation

### Accounting guardrails

- [x] **`revenueBonusSupplier`** scaled by **external share** of fulfilled capacity (not full bonus per owned customer)
- [x] Internal customer benefits remain **cost reduction / reliability** only
- [x] Unit-level revenue on cards may show “effective” revenue; debrief shows consolidated external total

## Phase 3 — Negotiation supply leverage

Deterministic leverage from owned chain position; AI roleplays only.

### Engine

- [x] **`computeSupplyLeverage(state, counterparty, context)`** — doc formula:  
  `criticality × playerShare × (1 − alternatives) × (1 − buffer)`
- [x] Inputs from template tags, owned suppliers, diligence intel, relationship memory
- [x] Cap leverage (e.g. max 0.55) so coercion never auto-wins
- [x] **`applyLeverageToUtility(utility, leverage, direction)`** in negotiation path (relationship + acquisition where relevant)

### Consequences (lightweight)

- [x] High leverage success: small **reputation** cost or **trust** hit with counterparty species
- [x] Repeated monopoly play: increased rival contest frequency or “alternative supplier” intel line (copy only OK for 6.0)

## Phase 5 — Infrastructure tollbooth & export channel

### Infrastructure external revenue

- [x] **Repair Shed / Cold Storage:** split value into  
  - `internalServiceValue` → synergy cost savings (existing)  
  - `externalContractRevenue` → fills **unused capacity** → adds to portfolio revenue (rent-like)
- [x] Utilization &gt;85%: strain penalties (delays, weaker crisis bonus, higher opex) — deepen existing strain
- [x] Utilization &gt;100%: unfulfilled requests + relationship/copy penalties

### Export floor (strategic edge or default mechanic)

- [x] **Bulk Commodity Exporter** edge OR baseline export slot for upstream assets
- [x] Purchases unused capacity at **floor price − logistics** (worse than good local link)
- [x] Volume cap per turn; visible in allocation UI as “Export (floor)”

### Tests / verify

- [x] Cold Storage at 50% utilization earns external contract revenue
- [x] At 100%+ utilization, external contracts drop or strain worsens
- [x] Export never beats a strong owned downstream link on pure economics
